# Labs 1–12 coverage matrix

Each Academy lab maps to a part of the UrbanFlow 2.0 solution. Each row lists the component, its source, the tests that check it, the live evidence and an honest status.

**Live evidence:** Final Project live results come only from approved Final Project runs, recorded in [RELEASE_AND_VALIDATION.md](RELEASE_AND_VALIDATION.md) and `evidence/`. The individual labs and Demo 3 were validated live in their own folders. That is their evidence, not Final Project evidence, and none of it is copied here. In Personal DEV on 2026-10-12, these passed: step 2 (platform sample run), step 3 (strict idempotency), step 4 (CDC inserts, updates, deletes and replay, including the checkpoint across an automatic `OPTIMIZE`) and step 5 (Lakeflow). The assistant, Zerobus, dashboard data, governance and PROD have not run live yet.

## Status vocabulary

| Status | Meaning |
|---|---|
| **Implemented, tested offline** | Code is complete. Unit tests, local Spark tests or static checks pass in CI. Not yet run in a workspace. |
| **Implemented, opt-in** | As above, but only runs when a reviewer switches it on, because it is billable or needs an approved identity or resource. |
| **Optional** | Not part of the platform Job. It is isolated by design and the platform does not depend on it. |
| **Validated live (DEV)** | A Final Project run ID and its independently verified result are recorded for this lab's capability in Personal DEV. |
| **Partially validated live (DEV)** | Part of the capability was verified in a recorded Final Project run; the row says which part is still offline only. |
